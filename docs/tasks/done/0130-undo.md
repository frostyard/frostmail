# T-0130: Undo moves, deletes and flag changes with Ctrl+Z

## Goal

Edit → Undo, as in Mail.app: Ctrl+Z takes back the last move, delete,
archive, spam move, flag or read change made in the main window.

## Read first

- `docs/specs/ui.md`: "Behavior", the Undo bullet, and the keyboard map;
  [ADR-0028](../../adr/0028-mute-and-block-in-maild-undo-in-the-app.md).
- `app/src/app/commands.ts` (`toggleRead`, `toggleFlag`, `setFlagColor`,
  `moveMessages`, which archive, spam moves, drag and drop and the menus
  all use), `app/src/app/MainWindow.tsx` (`onDelete`, `mailCommand`) and
  `app/src/lib/keymap.ts`.
- `app/src/rpc/gen/api.ts`: `message.summaries`, `message.move`,
  `message.copy`, `message.setFlags`, `FlagChanges`.
- The given tests; `docs/tasks/EXECUTOR.md`.

## Contract

- **`app/src/app/undo.ts`** exports:
  - `UNDO_LIMIT = 20`.
  - `UndoCall`: `{method: "move", params: {ids, mailboxId,
    fromMailboxId}}`, `{method: "copy", params: {ids, mailboxId}}` or
    `{method: "setFlags", params: {ids, changes}}`.
  - `useUndo`, a zustand store `{entries: UndoCall[][]}`, oldest first,
    at most `UNDO_LIMIT` (the oldest dropped).
  - `moveBack(before, after)`: for each message of `before` found in
    `after`, the mailboxes it left and entered (in `mailboxIds` order).
    With one or more entered: a `move` to the first it left from the
    first entered, and a `copy` to each other it left; with none
    entered, a `copy` to each it left; none left, nothing. All moves come
    before all copies; calls equal but for their messages are merged
    into the first, the messages in order.
  - `flagsBack(before, changes)`: for each message whose value differs
    from what `changes` set, a `setFlags` with its earlier `seen`, and
    one with its earlier `flagColor` (0 when not flagged); merged as
    above.
  - `undoableMove(client, ids, act)`: `message.summaries {ids}`, then
    `act()`, then the summaries again, remembering `moveBack` unless it
    is empty. No ids: nothing.
  - `undoableFlags(client, ids, changes)`: the summaries, then
    `message.setFlags {ids, changes}`, remembering `flagsBack` unless it
    is empty.
  - `undo(client)`: takes the newest entry off the store and makes its
    calls in order; resolves false when there was none.
- **`commands.ts`**: `toggleRead`, `toggleFlag` and `setFlagColor` set
  their flags through `undoableFlags`; `moveMessages` moves through
  `undoableMove`.
- **`MainWindow.tsx`**: `onDelete` deletes through `undoableMove`; the
  command `undo` runs `undo(client)` in the mail module (a failure only
  logs).
- **`keymap.ts`**: Ctrl+Z is the command `undo`; it is not allowed in a
  text field, so a field keeps its own undo.

## Gotchas

- A message ID stays the same across moves, so the summaries after a
  move or delete name the same messages.
- Opening a message marks it read in `ReaderContainer`; leave that alone,
  it is not undone.
